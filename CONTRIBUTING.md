# Contributing and updates

Useful contributions include independent reproductions, corrected mathematical or implementation details, stronger matched baselines, and external-market evaluation.

For a reproduction, report the data provider, coverage, input hashes, Python/library versions and commands. Keep the target definition, label maturity and time split explicit. Publish failures and uncertainty as well as gains.

For an updated snapshot, retain the prior report and create a dated release. Record the data cutoff and retrieval time separately. Synchronize every dated figure/table with its inputs. Recompute input-dependent caches. Never relabel a historical percentile as a crisis probability.

Method changes should include a regression check that can reveal the changed behavior. Additional tuning after seeing test results is exploratory; record it. Separate descriptive market-state plots from evaluated future forecasts.

Use issues for reproducible bugs and research questions, and pull requests for concrete changes. Avoid uploading unlicensed raw market data, personal records, API credentials or copied publisher figures.

No automatic update schedule or monitoring service is currently configured.
